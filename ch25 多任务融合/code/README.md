# ch25 多任务融合 — 代码示例

本目录对应教材第 25 章，按方法演进组织 7 组可运行示例：人工公式、自动寻参、学习式融合与排序学习，以及 IntEL、UMRE、EMER、HarmonRank 四篇论文的方法模块。代码使用 PyTorch 和小规模 **[MOCK] 合成请求日志**，用于检查关键结构、损失和梯度路径；不声称复现论文实验数据或线上指标。章节 PDF 的页码尚待正式审阅，以下以节次定位。

## 快速运行

依赖 Python 3.10+ 和 PyTorch。进入本目录后执行：

```bash
python3 verify_all.py
python3 ch01_manual/fusion.py
python3 ch02_search/search.py
python3 ch03_learned_ltr/learned_ltr.py
python3 ch04_intel/intel.py
python3 ch05_umre/umre.py
python3 ch06_emer/emer.py
python3 ch07_harmonrank/harmonrank.py
```

所有入口在 CPU 上运行，固定随机种子 42；训练脚本使用真实的 PyTorch 自动微分和优化器更新参数。`common.py` 负责生成数据，不是单独的训练入口。运行结果是合成任务上的检查值，不用于不同论文方法的效果比较。

## 正文与实现对应

### §25.2 人工设计的融合

- **预测值融合**：加权和，以及原文的 `∏(βₘ + αₘpₘ)^γₘ` 乘法形式；乘法底数非正时明确报错，防止分数成为 NaN。
- **Rank 融合**：每个请求、每个目标先对候选排序，再对归一化名次求加权倒数。严格单调变换预测值不会改变该分支的结果。
- **值序混合**：每个目标同时使用预测值和名次，计算加权的 `pₘ/rₘ`。权重与变换函数是教学配置，需按具体业务标定。

### §25.3 自动化参数寻优

- 同一加权公式下给出网格搜索、随机搜索、RBF 高斯过程代理加置信上界采集，以及交叉熵方法的精英样本分布更新。搜索仅改变参数，不暗中改变融合函数。
- 演示目标是在有反馈的已曝光候选上计算请求内偏好一致性；训练集寻优、留出集报告结果。该指标是 **[MOCK] 离线代理**，不是在线业务收益；线上实验的流量、延迟和反馈时效约束需要另行建立。

### §25.4–25.5 学习式权重和 Learn to Rank

- `GlobalFusion` 学习一组全局目标权重；`DynamicFusion` 用用户、物品和上下文生成候选级权重。两者用 Softmax 保证权重非负且和为 1。
- `LTRFusion` 将预测值和辅助特征输入排序网络，提供 Pointwise MSE、Pairwise Logistic 和 Listwise Plackett–Luce（P-L）三个训练目标。P-L 需要全排列；相同反馈等级按候选原顺序稳定破平局，这是教学数据约定，不表示同级物品存在真实偏好。
- 所有依赖真实行为标签的训练仅使用已曝光候选。该示例不含反事实估计，不能把未曝光标签当作真实负例。

### §25.6 IntEL（SIGIR 2023）

- 输入包括独立训练并冻结的上游目标预测、物品类别、历史 Session 意图与其发生时的上下文、历史正反馈交互和当前环境上下文。Session 与物品两个粒度分别用 GRU 编码，再通过 Softmax 预测类别×行为联合意图。
- 每个基础目标的分数列表分别经过候选间自注意力，再聚合目标表示；类别列表有单独的自注意力。完整意图向量作为两个交叉注意力的共享 Query，随后生成每件候选物品的归一化基础模型权重，并对固定基础分数加权求和。
- 联合目标采用论文 Pointwise 情形：已曝光候选的 MSE、非负归一化权重下可精确验证的 EA 模糊性项，以及真实意图分布的 KL 损失。书中 BPR/P-L 的 EA 推导含跨物品权重差异条件，代码没有把 Pointwise 方差公式直接冒充为这些损失的精确模糊性项。
- **原文公式的一个退化点**：若把同一用户意图复制为每件物品的 Query，交叉注意力输出会逐物品相同。代码保留列表注意力的物品局部残差，才能生成论文目标中的物品级权重；此处是明确的实现选择，不能称为仅由原文式 (26)–(28) 唯一推出。
- 论文的列表编码提及 Cross-Relation Attention；本教学实现使用常规多头自注意力保留列表交互语义，未复刻该引用模块的内部实现。论文发布的工程代码没有直接纳入本仓库，具体算子与超参仍需以其原始实现复核。

### §25.6 UMRE（arXiv:2508.07613）

- 每个预测目标有独立积分网络；`ELU(MLP)+1` 使被积函数严格为正，从 0 到原始 pXTR 的积分形成严格单调变换。使用论文附录的 32 节点 Clenshaw–Curtis 求积和目标专属可学习偏置；被积函数的用户/物品上下文在比较同一目标的两个分数时保持固定。
- 物品、类别、行为三种历史嵌入顺序输入 GRU；用户表示分别查询变换后目标分数 token 与类别 token，两个交叉注意力输出加用户表示产生融合权重。按原文线性头输出权重，**未额外施加 Softmax**，最终对已变换分数加权求和。
- 用多行为反馈加权得到全局奖励，并对最终分数计算 MSE。预热后按 UAUC 变化调整奖励权重；代码按用户汇总其适配集内全部已曝光样本、计算各有效用户的 AUC 再平均。原论文 Algorithm 1 的 `δ=γ(UAUC_prev−UAUC_current)` 与 `ω_next=ω−δ` 同其“指标下降应增权”的文字解释方向相反；代码依据正文公式 `ω_next=ω−γ(UAUC_current−UAUC_prev)` 和解释执行，并在机制检查中固定这一行为。合成结果不能证明 Pareto 最优。
- 被积函数采用三层残差 MLP 和积分位置的正弦/余弦编码；隐藏维度由论文附录的 128 缩至 64，以便 CPU 教学运行。类别注意力的 Key/Value 加入当前候选与历史类别，避免单个类别 token 的注意力退化；这是示例的输入适配，论文未给出这一步的唯一张量组织方式。求积的参数梯度使用 PyTorch 自动微分，未实现附录所述的 Leibniz 定制反向内存优化，不声称复刻完整实验超参或开销。

### §25.6 EMER（arXiv:2508.05093）

- 一个请求内的已曝光和未曝光候选共同进入 Transformer；输入含用户/物品/上下文特征、各目标 pXTR，以及每个目标在请求内的归一化名次。候选互相影响打分，保持列表级建模。
- **后验损失**只根据已曝光物品的正反馈数量建立“多种正反馈 > 单种 > 无正反馈”的 Pairwise Logistic 监督；**先验损失**在全部候选上，分别按每个 pXTR 的相对高低建立 Pairwise BCE，不将目标预先合成单一标签。
- Advantage Evaluator 使用“上一版本指标 / 当前版本指标”更新各先验损失权重；在教学流程中，两个版本是在同一适配集上连续评估得到，最终测试集独立，并非论文线上 serving/training 双模型。第三目标的互动率除以预测观看秒数演示 IPUT，并做分母保护；这只是单位时间互动效率代理，不是 Session 累计互动收益。

### §25.6 HarmonRank（arXiv:2601.02955）

- 对每个目标的标量分数做等距分桶嵌入，目标间自注意力对齐共性；用户与上下文作为 Query 对齐目标表示，得到关系感知分支。另两条分支分别对原始目标嵌入做门控和直接线性融合，最终三分支相加。
- 训练目标按升序秩和写成多目标 AUC。由于硬排序不可导，使用原文的“向排序位置置换多面体投影”目标；升序排序后用 PAVA 等距回归计算前向投影，反向在每个合并块内使用精确的局部 Jacobian。机制检查覆盖相等分数的平均秩、相距足够大时的硬秩、非零梯度和 AUC 秩和等价性。
- 原文将 `B` 同时描述为桶数并写出 `floor(s/B)`；对于本例 `[0,1]` 输入，代码用 `floor(s×B)` 构造 `B` 个等距桶并截断边界，属于对该符号歧义的显式处理。Python PAVA 展示算法机制，不代表论文的生产级并行性能。

## 合成数据、验证与边界

### 与原论文的一致性结论

四个论文脚本均为可训练的**关键机制教学实现**，不能称为完整论文复现。核对原文后，仍有以下明确差异：

| 方法 | 已核对并实现的核心 | 尚未复现的部分 |
| --- | --- | --- |
| IntEL | 两级历史意图、按基础目标列表编码、意图引导融合、Pointwise EA 与 KL | Cross-Relation Attention 的具体算子；论文离线构造候选时还并入当前 Session 正样本，本例为防止生成时标签泄漏，只从预训练分数选候选 |
| UMRE | 各目标正值积分、历史 GRU、双交叉注意力、按用户 UAUC 调权 | 论文完整数据与超参；积分的定制反向内存优化；原文 Algorithm 1 符号冲突按正文解释处理 |
| EMER | 请求级候选互看、曝光反馈后验、全候选多目标先验、AE 比值、IPUT | 线上 serving/training 版本对比和 Session 累计收益；本例用同一适配集的相邻训练版本近似 AE |
| HarmonRank | 三分支目标关系、AUC 秩和、置换多面体投影及梯度 | 论文的生产并行实现、真实目标定义与实验设置；分桶公式按原文文字解释处理 |

独立测试损失和参数变化只能证明代码在该合成任务上执行了优化，不能证明论文方法整体忠实、指标提升或线上收益。

`common.py` 默认生成 256 个按时间排列的请求，每请求 8 个候选、3 项行为目标，含 32 个稳定用户、180 个稳定物品、类别与稠密属性。先在与融合请求不重叠的 2048 条早期合成反馈上训练上游多目标预测器 30 步并冻结；pXTR 来自该模型推断。每个请求从各目标 Top 候选形成并集，按位置相关 propensity 采样曝光，仅已曝光候选有可观测反馈；历史只追加此前的正反馈，并保存行为时间和历史 Session 上下文。当前意图标签由当前已曝光正反馈构造，仅用于监督。

常规示例沿用时间排序的训练/留出切分；四个论文入口使用训练、适配、最终测试的 60%/20%/20% 时间切分。UMRE 和 EMER 仅在适配集更新动态权重，最终测试集不参与训练或调权。测试日志逐请求滚动，后续请求的历史可以包含此前已观测行为。数据仍标为 **[MOCK]**：真实候选策略、延迟反馈、pXTR 校准和线上模型版本均未复刻。代码虽记录已知的曝光 propensity，损失尚未实施 IPS/DR 反事实校正，不能据此声称消除曝光偏差。

`verify_all.py` 的七组检查分别覆盖数据实体一致性、Rank 单调不变性、动态权重梯度、IntEL 物品级权重及 EA 恒等式、UMRE 正值积分及求积、EMER 先验与后验的曝光边界、HarmonRank 投影与秩和。这些检查比“能跑通”更强，但仍不能代替论文级数据、超参、消融与线上实验复现。

在固定种子 42、CPU、默认 256 请求下，七个入口和七组检查均通过。四个论文入口的独立测试集结果如下；括号内是训练前、训练后，UMRE 和 EMER 的两次损失都按**最终**动态权重计算，因此可直接比较同一目标值：

| 方法 | 独立测试指标 | 选定关键参数变化的 L2 范数 |
| --- | --- | ---: |
| IntEL | 目标损失 0.3598 → 0.3189 | 0.4781 |
| UMRE | MSE 0.2768 → 0.1012 | 0.2654 |
| EMER | 后验加先验损失 1.3992 → 1.3711 | 1.0523 |
| HarmonRank | 负 AUC 秩和 -0.4998 → -0.5016 | 0.3089 |

这些数值是一次确定性教学运行的诊断记录；四个损失的尺度和含义不同，不能跨方法排序，也不能据此推断真实推荐效果。

真实部署还需确定候选规模、线上延迟与吞吐、预测值校准和版本一致性、曝光偏差与延迟反馈、指标护栏、过载降级及回滚方案。本目录只提供单机 CPU 教学实现，不包含生产特征服务、分布式训练、线上 A/B 或容量结论。
