# 向量索引换代：教学验证案例

此案例使用仓库合成向量和 `[MOCK]` 查询，演示发布契约与故障拒绝；不包含真实训练、ANN 构建或线上流量。适用于「模型收益已确认，索引切换时如何避免版本混用」的工程讨论。

## 本书依据

《第十八章-向量检索系统.pdf》，PDF 第 42–46 页（索引参数及构建、切换）；相关版本协同还需对照《第十七章-推荐系统在线服务.pdf》，PDF 第 16–24 页。引用页只作为阅读入口，具体发布清单属于下方扩展设计。

## 工程实现

发布清单应同时绑定模型、物品向量、索引、特征 schema 与请求路由的版本号。灰度前固定测试查询和候选集，对比旧版与新版的候选覆盖、相似度排序和延迟。切换时只允许同一发布清单内的物品向量与查询模型参与检索；不兼容请求应拒绝或回退到已知兼容的旧版。

## 本地演练

在仓库根目录运行：

```bash
python3 templates/two-tower-ann/app.py --user u1 --limit 3
python3 templates/two-tower-ann/app.py --user u1 --limit 3 --inject-version-mismatch
```

第一条观察固定向量的精确排序；第二条观察版本不匹配被拒绝。记录退出码和输出，再说明：若真实 ANN 索引换代，如何做双读比较、索引预热、灰度与整套回滚。上述脚本没有证明 ANN 召回率或 P99。

## 验证与待确认

真正验收需在相同查询集合下记录 Recall@K、长尾覆盖、P50/P99、索引新鲜度、空结果率和回退原因；故障注入覆盖旧模型配新索引、索引加载失败、部分分片未就绪。单副本容量、SLO、灰度流量、回滚耗时与真实数据隐私约束须由部署环境确认。实验结论只在有实测日志后填写。
