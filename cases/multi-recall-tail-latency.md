# 多路召回延迟突增案例

## 现象
仅部分请求的召回阶段 P99 上升，并触发下游候选不足；平均延迟变化不明显。

## 匿名化证据
- 单召回路 RPC 延迟分布出现长尾；
- 总请求 timeout 固定，但子调用未设置更短 deadline；
- 超时后仍等待同批其他调用结束；
- 兜底候选数量充足。

## 根因与处理
慢依赖占满总预算且缺少隔离。为该路设置独立 deadline 和并发上限，超时立即用其他路结果继续；保留非空兜底。

## 验证
故障注入下检查端到端 P99、该路超时率、候选量和非空返回率。

## 本书依据
《第十七章-推荐系统在线服务.pdf》，PDF 第4页的超时预算，以及稳定性治理相关页面。
