ANN 的成本直觉：为什么要做近似搜索（第18章 §18.1） 正文给的算例：物品库 N=10^9、向量维度 d=128，一次精确检索约需 N × d ≈ 10^11 次浮点运算 即使在高性能服务器上也难以满足毫秒级响应。 本脚本做四件事： 1) 复现这个算例，并把它换算成"单核每秒 10 亿次浮点运算"下的耗时与吞吐； 2) 在本机真实测量 NumPy 暴力检索的吞吐，用实测值再算一遍（数字更具体）； 3) 计算存储成本：float32 / int8 / PQ 三种编码下 10^9 个向量各占多少内存； 4) 打印"只扫描 x% 的库、召回率还能保持多少"的权衡表——这是所有 ANN 算法 共同的 trade-off，后面的 KD 树、PQ、HNSW 只是用不同方式实现这个扫描比例。 [MOCK]：机器算力（10 GFLOPs）、内存带宽、内存价格按典型云主机量级取整
